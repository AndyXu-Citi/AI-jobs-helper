# 前端设计评审 — AI 求职 Agent v3.0（src/web/static/index.html）

> 评审对象：单文件原生 HTML/CSS/JS（1677 行，无框架、无构建步骤）
> 评审视角：前端工程（可维护性 / 可访问性 / 性能 / 一致性 / 安全）
> 结论：**整体能用、视觉统一、功能完整**；问题集中在「可访问性缺失」「重复/失控的 markup」「可维护性债」三类，无致命阻断，但有几处真实 bug。

---

## 一、当前前端结构

```
index.html (单文件)
├─ <style>   行 8-495   纯 CSS，暗色主题，~487 行
├─ <body>    行 497-651  5 个 Tab + 对应视图（全静态结构）
└─ <script>  行 655-1674 全部逻辑：Tab 切换 / Agent / 岗位库 / 报表 / 匹配 / 面试
                          ↓ fetch
                       FastAPI（API='' 同源）
```

优点（先肯定）：
- **零构建、零依赖**：一个 HTML 文件双击即开，部署成本极低，契合个人工具定位。
- **主题统一**：`#4fc3f7` 主色 + 暗色背景贯穿全站，视觉一致。
- **岗位库 master-detail 分栏**（`jobs-split-layout`）交互合理，移动端有 `@media` 降级。
- **XSS 防护基本到位**：岗位/聊天等「不可信数据」（Boss 抓取内容、LLM 输出）大多过 `escapeHtml()`。

## 二、问题清单（附 file:line 证据）

### P0 — 真实 Bug：面试模式「两套并行控件」且其中一个是死模式

`AI 面试` 设置面板里，**同一件事出现了两套不互通的按钮**：

- 行 624-628：4 个 `<button class="mini" onclick="setInterviewMode(...)">`
  - `resume` / `chain` / `knowledge` / `jd`
  - 文案：弱点探查 / **追问链** / 知识检索 / JD 调取
- 行 632-637：4 个 `<span class="mode-tag" data-mode="...">`（真正生效的选择器）
  - `resume` / `project` / `knowledge` / `jd`
  - 文案：简历深挖 / **项目拷问** / 知识点 / 指定 JD

三处错配：
1. **标签不一致**：同一 mode 用户看到两个名字（如「简历深挖」vs「弱点探查」、「项目拷问」vs「追问链」）。
2. **`chain` 是死模式**：`MODE_LABELS`（`index.html:1443-1448`）只有 `resume/project/knowledge/jd`，**没有 `chain`**。点「追问链」→ `setInterviewMode('chain')` → `querySelector('[data-mode="chain"]')` 返回 `null` → 既不动高亮，又把 `_interviewMode` 设成 `'chain'` → `startInterview()` 把这个非法 mode 发给后端（后端无对应 prompt）。
3. **两端会打架**：`setInterviewMode()` 内部只更新 `mode-tags` 那组；mini 按钮点了之后视觉无反馈，但状态已被篡改。

`newInterviewChat()`（行 1469-1495）重建面板时**原样复制了这套错误**（1474-1477 仍是 residue/project/knowledge/jd）。

**修法**：删掉行 624-628 的 mini 按钮整行（或删掉 632-637 的 mode-tags，二选一保留），并以 `MODE_LABELS` 的 4 个 key 为唯一真源。建议保留 `mode-tags`（语义更清晰），删 mini 行。

### P1 — 可访问性（A11y）缺失

| 问题 | 位置 | 影响 |
|---|---|---|
| Tab 是 `<span onclick>`，无 `role`/`tabindex`/`keydown` | 行 508-512、661-672 | 键盘用户**无法聚焦、无法切换** Tab，纯鼠标才能用 |
| 面试模式/技能筛选均为 `<span onclick>` | 行 632-637、1004、1058 | 同上，全部无法键盘操作 |
| 无 `aria-live` 区域 | 全局 | 「加载中 / 报错 / 思考中」屏幕阅读器不播报 |
| `.tab`/`.mode-tag` 无 `:focus-visible` 样式 | 全局 | 键盘聚焦时无可见焦点环 |
| `aria-hidden`/语义标签缺失 | 全局 | 整页基本是 `<div>`+`<span>`，无 `<nav>`/`<main>`/`<section>` |

**修法**（低成本）：把 `.tab` 改成 `<button class="tab" role="tab">` + 监听 `keydown`（Enter/Space）；筛选/模式标签加 `tabindex="0"` + 同样键盘处理；加载/报错容器加 `aria-live="polite"`/`assertive`。

---

### P1 — 筛选每次全量重渲染

`renderJobLibrary()`（行 1039-1076）每次 `toggleSkill()` 都用 `area.innerHTML = html` **重建整个列表 + 详情面板**。136 条时尚可接受，但有两个副作用：
1. 列表滚动位置被重置；
2. 详情面板的展开/交互状态丢失（虽然当前详情无展开，但结构脆弱）。

**修法**：列表与详情拆成两个独立 DOM 节点，筛选只更新列表 `innerHTML`、按需调用 `renderJobDetail` 更新右侧，不动整体容器。或引入轻量虚拟滚动（数据上千条时才有必要）。

### P2 — 可维护性债

1. **行内样式泛滥**：几乎每个动态元素都带 `style="..."`（如 831、834、941、1120、1417…），`<style>` 块形同虚设。主题色硬编码在 JS 字符串里（如 `scoreColor '#66bb6a'`，行 1301），与 CSS 脱节。
2. **面试设置面板被维护两份**：静态 HTML（行 621-646）+ `newInterviewChat()` 里的 JS 字符串（行 1469-1495）内容几乎一致。改一处必忘另一处（正是 P0 bug 滋生的温床）。
3. **无 CSS 变量**：`#4fc3f7` 出现约 30 次、`#1a1a1a`/`#333` 遍及各处。想换肤/加亮色主题需全局替换。
4. **无组件化/无构建**：所有逻辑堆在一个 `<script>`，函数间靠全局变量（`_allJobs`、`_interviewSessions`、`_currentSessionId`…）隐式耦合，状态来源分散。

**修法建议**：抽 `:root { --accent: #4fc3f7; --bg: #0f0f0f; ... }` 变量；把面试设置面板抽成一个 `renderSetupCard()` 函数，静态/重建共用同一份模板字符串；颜色统一走 class。

---

### P2 — 对比度与动效偏好

- `.skill-filter .count`（`#666` on `#1a1a1a`，行 285-287）、`.detail-empty`/`#sidebar-empty`（`#555` 行 331、392）等小字对比度约 **2.3–3.0:1**，**低于 WCAG AA 的 4.5:1**。
- 所有动画（`fadeIn`/`spin`/`pulse`，行 38、106、487）**未包裹 `prefers-reduced-motion`**，前庭功能障碍用户无法关闭动效。

---

### P3 — 死代码 & 小问题

- **`loadJobs()`（行 917-955）从未被任何地方调用**——岗位库用的是 `loadJobLibrary()`（行 963）。整段是孤儿代码，可删。
- `markdownToHtml()`（行 874-884）**未对 LLM 输出做 `escapeHtml`**，直接 `innerHTML`。风险低（来源是自有 DeepSeek），但若模型被 prompt 注入返回 `<script>` 仍有 XSS 面。建议先 escape 再处理 markdown。
- `genReport()` 的提示文案「当前样本量较小」硬编码（行 569），与数据规模耦合。
- 返回顶部按钮（行 653）监听 `window` scroll，但岗位库/面试用的是**内部面板 `overflow-y:auto`**，在那些视图里「返回顶部」不生效（小问题）。

## 三、分阶段改进路线图

| 阶段 | 项 | 优先级 | 工作量 |
|---|---|---|---|
| **阶段一（正确性）** | 修 P0 面试双控件/死 `chain` 模式；删死代码 `loadJobs` | P0/P3 | 0.5h |
| **阶段二（可用性）** | Tab/筛选改 `<button>`+键盘可达；加载/报错加 `aria-live` | P1 | 1.5h |
| **阶段二** | 筛选改为局部重渲染，不重建整容器 | P1 | 1h |
| **阶段三（维护性）** | 抽 CSS 变量 + 面试面板模板函数；颜色/行内样式收敛 | P2 | 2h |
| **阶段三** | 对比度提至 AA + `prefers-reduced-motion` 包裹动画 | P2 | 1h |
| **阶段三** | `markdownToHtml` 先 escape 防注入 | P2 | 0.5h |

> 若目标是「求职作品集展示」，**阶段一 + 阶段二** 最值得先做（直接影响面试官能否顺畅试用、能否键盘操作）；阶段三属长期健康度，可后续迭代。
